# TC05 — Recover a PDF upload after restoring Wi-Fi

Suite: Offline and Network Settings

Verify that a PDF upload attempted while offline can be completed after Wi-Fi is restored, either automatically or through an available retry action.

## Preconditions

1. Environment: ENV-001 — Samsung Galaxy S24 FE, Android 16, One UI 8.5, Google Drive 2.26.387.

2. The user is signed in to Google Drive.

3. The Google account has sufficient available storage.

4. A readable PDF smaller than 1 MB is stored locally as TC05_R01_document.pdf.

5. The destination folder QA-Connectivity-Lab exists and contains no file with that name.

6. No other uploads are pending.

7. A working Wi-Fi connection is available.

8. The desktop browser has independent internet access and is signed in to the same Google account.

9. The device's initial connectivity and Wi-Fi-only transfer settings are recorded for restoration after the test.

## Procedure

| Step | Action | Expected result |
|---|---|---|
| 1 | Open the local PDF and note its page count and content. While connected, open QA-Connectivity-Lab in Google Drive. | The PDF is readable and the destination folder opens successfully. |
| 2 | Disable Wi-Fi and mobile data on the phone. Ensure no alternative internet connection is active. | The phone has no active internet connection. |
| 3 | Attempt to upload TC05_R01_document.pdf. Observe for 30 seconds and record the status. | The upload is not reported as completed. The app indicates an offline, pending, waiting, or unsuccessful state. |
| 4 | Enable Wi-Fi, confirm internet access, and keep mobile data disabled. Return to Google Drive. | Wi-Fi connectivity is restored and the app remains usable. |
| 5 | Observe whether the upload resumes automatically. If it does not, use an available retry or upload action. Record the action taken and avoid starting another upload while one is active. | The upload resumes automatically or can be restarted through a clear user action. |
| 6 | Wait for the upload to finish and record the final status and approximate recovery time. | The file appears with no pending upload or error indicator. |
| 7 | Refresh QA-Connectivity-Lab in the desktop browser. | Exactly one file named TC05_R01_document.pdf is listed. |
| 8 | Open the uploaded PDF on the desktop and compare it with the local original. | The PDF opens, and its page count, text and visible content match the original. |

## Postconditions

1. Keep the uploaded file in the destination folder until evidence collection is complete.

2. Ensure no upload from this case remains pending.

3. Restore the device's initial connectivity and transfer settings after evidence collection.
