# TC15 — Retry an interrupted upload without creating duplicate files

Suite: App Lifecycle and Retry

Verify that using an explicit retry action after an interrupted upload results in one complete, readable file in the destination folder.

## Preconditions

1. Environment: ENV-001 — Samsung Galaxy S24 FE, Android 16, One UI 8.5, Google Drive 2.26.387.

2. The user is signed in to Google Drive.

3. The Google account has sufficient available storage.

4. A playable MP4 video without personal information is stored locally as TC15_R01_video.mp4.

5. The video is large enough to interrupt an active upload. Start with approximately 20–50 MB and adjust if needed.

6. The destination folder QA-Connectivity-Lab exists and contains no file with that name.

7. No other uploads are pending.

8. Wi-Fi is connected with working internet access. Mobile data is disabled and no alternative connection is active.

9. The desktop browser has independent internet access and is signed in to the same Google account.

10. The device's initial connectivity and transfer settings are recorded for restoration after the test.

11. Exercising this case requires the app to expose an explicit retry action for the interrupted upload.

## Procedure

| Step | Action | Expected result |
|---|---|---|
| 1 | Open the local video. Record its file size and duration, and check playback at the beginning, middle, and end. | The video plays correctly. Reference details are recorded for comparison. |
| 2 | Open QA-Connectivity-Lab and start uploading TC15_R01_video.mp4 over Wi-Fi. | The upload is visibly in progress. |
| 3 | Disable Wi-Fi before the upload finishes. Keep mobile data disabled. | Connectivity is interrupted during the upload. |
| 4 | Observe for 30 seconds. Record the upload state, message, and whether an explicit retry action is available. | The upload is not falsely reported as completed. The availability or absence of a retry action is documented. |
| 5 | Restore Wi-Fi and confirm internet access. Check whether the interrupted upload still offers a retry action. | The retry action is available for the incomplete upload. If the app automatically recovers and no retry action is available, stop this case and record that the required condition was not reached. |
| 6 | Capture evidence of the retry action, then select it once. Do not start a separate upload through the New or Upload menu. | The retry request is accepted and the interrupted upload restarts or resumes. |
| 7 | Wait for completion and record the final status. | The upload completes with no pending upload or error indicator. |
| 8 | Refresh QA-Connectivity-Lab in the desktop browser. Inspect the folder for the original filename and any automatically renamed copies of the same video. | Exactly one resulting video file is present, named TC15_R01_video.mp4, with no unexpected duplicate copies. |
| 9 | Download the uploaded video on the desktop. Compare its size and duration with the original, and check playback at the beginning, middle, and end. | File size and duration match the original. The checked sections play without visible or audible corruption. |
| 10 | Open the original video on the phone again. | The local original remains available and playable. |

## Postconditions

1. Preserve the resulting file or files and evidence until review is complete, including any suspected duplicates.

2. If the case could not proceed, capture the observed recovery behavior before cleanup.

3. Ensure no upload from this case remains pending; cancel it if necessary and available.

4. Restore the device's initial connectivity and transfer settings after evidence collection.
