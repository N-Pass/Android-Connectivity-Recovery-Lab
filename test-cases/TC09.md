# TC09 — Recover an in-progress upload after mobile data interruption

Suite: Network Interruption and Recovery

Verify that an active upload interrupted by loss of mobile data can be completed after mobile data is restored, without misleading completion status or unexpected duplication.

## Preconditions

1. Environment: ENV-001 — Samsung Galaxy S24 FE, Android 16, One UI 8.5, Google Drive 2.26.387.

2. The user is signed in to Google Drive.

3. The Google account has sufficient available storage.

4. A playable MP4 video without personal information is stored locally as TC09_R01_video.mp4.

5. The video is large enough for the upload to remain active while mobile data is manually disabled. Start with approximately 20–50 MB and adjust if needed.

6. The destination folder QA-Connectivity-Lab exists and contains no file with that name.

7. No other uploads are pending.

8. Wi-Fi is disabled. Mobile data has working internet access, and no alternative connection is active.

9. Google Drive's "Transfer files only over Wi-Fi" setting is disabled.

10. The desktop browser has independent internet access and is signed in to the same Google account.

11. The mobile carrier, observed network type, and initial connectivity and transfer settings are recorded in the execution notes.

## Procedure

| Step | Action | Expected result |
|---|---|---|
| 1 | Open the local video. Record its file size and duration, and check playback at the beginning, middle, and end. | The video plays correctly. Reference details are recorded for comparison. |
| 2 | Open QA-Connectivity-Lab and start uploading TC09_R01_video.mp4 over mobile data. | The app shows that the upload is in progress without requiring Wi-Fi. |
| 3 | While the upload is visibly in progress, disable mobile data. Keep Wi-Fi disabled. | Connectivity is interrupted before upload completion. |
| 4 | Observe for 30 seconds. Record the upload status and any message displayed. | The app does not falsely report successful completion. The incomplete operation remains identifiable, and the app does not crash. |
| 5 | Keeping the phone offline, refresh the destination folder in the desktop browser. | No complete, downloadable copy of the video is available. If one is available, investigate whether the upload finished before the interruption took effect. |
| 6 | Enable mobile data, confirm internet access, and return to Google Drive. Keep Wi-Fi disabled. | Mobile connectivity is restored and the app remains usable. |
| 7 | Observe whether the upload resumes automatically. If necessary, use an available retry or upload action without creating another active upload. Record the recovery action and approximate time. | The upload resumes or can be restarted through a clear user action. |
| 8 | Wait for completion, then refresh the destination folder on the desktop. | Exactly one file named TC09_R01_video.mp4 is listed, with no pending upload or error indicator in the Android app. |
| 9 | Download the uploaded video on the desktop. Compare its size and duration with the original, and check playback at the beginning, middle, and end. | File size and duration match the original. The checked sections play without visible or audible corruption. |
| 10 | Open the original video on the phone again. | The local original remains available and playable. |

## Postconditions

1. Keep the uploaded file and collected evidence until review is complete.

2. Ensure no upload from this case remains pending.

3. Restore the device's initial connectivity and transfer settings after evidence collection.
