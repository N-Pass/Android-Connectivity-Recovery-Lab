# TC10 — Complete an upload after switching from Wi-Fi to mobile data

Suite: Network Interruption and Recovery

Verify that an upload started over Wi-Fi can be completed after switching to mobile data, with a consistent upload status and no unexpected duplication.

## Preconditions

1. Environment: ENV-001 — Samsung Galaxy S24 FE, Android 16, One UI 8.5, Google Drive 2.26.387.

2. The user is signed in to Google Drive.

3. The Google account has sufficient available storage.

4. A playable MP4 video without personal information is stored locally as TC10_R01_video.mp4.

5. The video is large enough for the upload to remain active during the network switch. Start with approximately 20–50 MB and adjust if needed.

6. The destination folder QA-Connectivity-Lab exists and contains no file with that name.

7. No other uploads are pending.

8. Wi-Fi is connected with working internet access. Mobile data is initially disabled and is available for the switch.

9. Google Drive's "Transfer files only over Wi-Fi" setting is disabled.

10. The desktop browser has independent internet access and is signed in to the same Google account.

11. The mobile carrier, observed network type, and initial connectivity and transfer settings are recorded in the execution notes.

## Procedure

| Step | Action | Expected result |
|---|---|---|
| 1 | Open the local video. Record its file size and duration, and check playback at the beginning, middle, and end. | The video plays correctly. Reference details are recorded for comparison. |
| 2 | Open QA-Connectivity-Lab and start uploading TC10_R01_video.mp4 while mobile data is disabled. | The upload starts over Wi-Fi and is visibly in progress. |
| 3 | While the upload is still active, enable mobile data and then disable Wi-Fi. Record the switch in the screen recording. | Wi-Fi is disconnected before upload completion, and mobile data becomes the available internet connection. |
| 4 | Confirm mobile internet access and return to Google Drive. Observe and record the upload status and any message displayed. | The app remains usable and indicates an active, pending, unsuccessful, or completed state consistent with the operation. |
| 5 | If the upload does not continue automatically, use an available retry or upload action without creating another active upload. Record whether recovery was automatic or manual. | The upload can continue or be restarted over mobile data without requiring Wi-Fi. |
| 6 | Keep Wi-Fi disabled until the upload finishes. Record the final status and approximate recovery time. | The upload completes with no pending upload or error indicator. |
| 7 | Refresh QA-Connectivity-Lab in the desktop browser. | Exactly one file named TC10_R01_video.mp4 is listed. |
| 8 | Download the uploaded video on the desktop. Compare its size and duration with the original, and check playback at the beginning, middle, and end. | File size and duration match the original. The checked sections play without visible or audible corruption. |
| 9 | Open the original video on the phone again. | The local original remains available and playable. |

## Postconditions

1. Keep the uploaded file and collected evidence until review is complete.

2. Ensure no upload from this case remains pending.

3. Restore the device's initial connectivity and transfer settings after evidence collection.
